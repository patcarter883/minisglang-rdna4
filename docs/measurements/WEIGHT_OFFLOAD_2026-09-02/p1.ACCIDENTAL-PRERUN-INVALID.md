# P1 — ACCIDENTAL PRE-RUN, VERDICT INVALID, KEPT ONLY AS EVIDENCE

**Do not cite the verdict in `p1.ACCIDENTAL-PRERUN-INVALID.json`. It says `PASS` at
690 GB/s and that number is not a host-memory read.**

## What happened

During implementation (2026-09-02, implement phase) a shape-check script imported
`tools/offload/p1_host_read_bw.py` as a module. At that time the script applied its
`ROCR_VISIBLE_DEVICES` fence at *import* time, and that fence `os.execve`s the process —
so the import replaced the shape-check process with a full default-argument run of the
probe on HIP device 0. It ran to completion (~25 s) before anyone could stop it. No lease
was involved (the lease is waived for this work); no other GPU job is known to have been
running, but that cannot be asserted.

The script has been fixed: the fence is now applied only under
`if __name__ == "__main__"`, so importing the module can never start GPU work.

## Why the run is kept

It produced a decision-critical result that changed the probe's design.

| arm (tiled, best config) | GB/s |
|---|---|
| `vmm_host` — hipMemCreate(**location=Host**) + hipMemMap onto a device VA | **690.4** |
| `vmm_dev` — hipMemCreate(location=Device) | 690.9 |
| `dev_plain` — plain `hipMalloc` | 690.4 |
| `pinned_default` — hipHostMalloc + hipHostGetDevicePointer | 28.9 |
| `pinned_noncoh` — hipHostMalloc(NonCoherent) + device pointer | 28.9 |

Copy-engine reference: `hipMemcpyAsync` H2D from ordinary pinned host memory = **28.7 GB/s**;
`hipMemcpyAsync` **from the `vmm_host` VA** = **313.5 GB/s**, i.e. the D2D rate (316.2), not
the PCIe rate.

Additional signals from the same record:

* VRAM free fell 15.86 → 13.71 GiB with four 512 MiB regions live — consistent with **all
  four** being in VRAM, including the nominally host-located one.
* `MemAvailable` moved by only −43 MiB across the whole run.
* The `vmm_host` VA was **not CPU-writable** (`readv` → `EFAULT`); its `/proc/self/maps`
  entry is a `---s` PROT_NONE mapping of `/dev/dri/renderD128`.

## The finding

`hipMemCreate` with `location.type = hipMemLocationTypeHost` (=2, confirmed against
`/opt/rocm/include/hip/driver_types.h:456`; the ctypes `hipMemAllocationProp` layout matches
`hip_runtime_api.h:1748` field for field) returns **`hipSuccess` for every chunk**,
`hipMemMap` and `hipMemSetAccess` both succeed, and a kernel reads the VA correctly — but
on this box (ROCm 7.2.53211, gfx1201, HIP device 0) the pages appear to be **VRAM, not host
RAM**. Every "host-page read bandwidth" derived from that mechanism — including the
withdrawn 127.2 GB/s in `vmm_probe2.py`, whose 2 MiB buffer would also have been VRAM — is
an HBM number wearing a host-memory label.

**This is unconfirmed until the real P1 run reproduces it with the placement-provenance
instrumentation.** It is recorded here because it is the reason that instrumentation exists.

## What changed in the probe as a result

`p1_host_read_bw.py` now refuses to let any arm into the verdict unless its pages are
*proven* host-resident:

1. `hipMemGetInfo` + `/proc/meminfo MemAvailable` sampled across backing **and** again after
   a full device-side touch of every page (drivers commit lazily).
2. All three host location types probed (`Host`, `HostNuma`, `HostNumaCurrent`); if a
   different one is genuinely host-resident it is measured as `vmm_host_alt`.
3. `hipPointerGetAttributes` recorded, never trusted alone.
4. Bandwidth cross-check: a tiled read above 2× the measured copy engine cannot have
   crossed PCIe → the arm is reclassified `device_resident`.
5. **Control:** the known-device VMM region must classify `device_resident`, or the method
   is declared unreliable and every placement claim in the record is voided.
6. If the plan's nominal mechanism fails, the verdict is computed from the substitute
   (`hipHostMalloc` zero-copy, host by construction) with `mechanism_substituted: true` and
   an explicit note that the substitute **cannot** provide T2's mixed device/host single VA
   stack.

Read the fresh `p1.json` / `p1.md` from the Run phase for the answer. This file is history.
